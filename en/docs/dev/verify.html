Checksums

Every figure for the release files, the signature, the law’s digests and the registry contract can be recomputed yourself.

Release files

Version 0.1.4 has six release files, with their checksums in the release list SHA256SUMS.txt:

On each system, compute one file and compare it with the table:

macOS
shasum -a 256 ZIKARON-0.1.4-macos-arm64.dmg
Linux
sha256sum zikaron-desk_0.1.4_amd64.deb
Windows
Get-FileHash ZIKARON-0.1.4-windows-x86_64.zip -Algorithm SHA256
PowerShell prints the value in capitals; compare it without regard to case.

On macOS and Linux you can also put the release list and the downloaded files in one folder and check them all at once:

macOS
shasum -a 256 -c --ignore-missing SHA256SUMS.txt
Linux
sha256sum -c --ignore-missing SHA256SUMS.txt

The third-party licences of the three platforms, THIRD-PARTY-LICENSES-macos.txt, THIRD-PARTY-LICENSES-linux.txt and THIRD-PARTY-LICENSES-windows.txt, are published separately, byte for byte the same as the copy in each package, and stay outside the release list. The drop zone on the download page does the same check: it computes the SHA-256 in the browser and compares it with the list.

Signature

On macOS the app and the dmg are signed with Kaptonia’s self-signed certificate; the pkg is checked by its SHA-256. Once installed, look at the app’s signature: Authority in the output should be Kaptonia, and Identifier should be com.kaptonia.zikaron.app:

codesign -dvv /Applications/ZIKARON.app

Then look at the signing requirement; the string after certificate leaf is the certificate’s SHA-1:

codesign -d -r- /Applications/ZIKARON.app

To compute the certificate’s SHA-256, extract the certificate first:

codesign -d --extract-certificates /Applications/ZIKARON.app shasum -a 256 codesign0
SignerCN=Kaptonia (self-signed)
Certificate SHA-256a6ddc371e855197c5021ef44ab0802749cda318bc12d0138ccac9f46a4d46905
Certificate SHA-1570690b34fc35243ae8b45be0aeb800e1074225e
Valid2026-09-26 to 2036-09-23

The dmg’s own signature can be checked the same way: codesign -dvv ZIKARON-0.1.4-macos-arm64.dmg.

The Windows zip and the Linux deb and AppImage are unsigned; check them by their SHA-256. On first start Windows says “Windows protected your PC”; click “More info”, then “Run anyway”. On Windows 11 with Smart App Control on, unsigned programs are blocked outright, so turn it off first.

Zikaron record

The code of each release is one commit. At release, the project records that commit and each release file’s fingerprint in its Zikaron ledger and anchors them on Ethereum mainnet: written once and final, with a block time; the “Zikaron record” column of the download table links to that transaction. Before 0.1.4 was published, these fingerprints were recorded as ten records and anchored in one transaction:

A file’s content fingerprint is the SHA-256 of its bytes; the two Windows programs each get a record of their own, to check one by one after unpacking the zip. The repository’s fingerprint is the SHA-256 of the current commit object; in a clone of the repository, run:

git cat-file commit v0.1.4 | shasum -a 256

What is anchored on chain is the entry IDs of these ten entries (the SHA-256 of each entry’s bytes), and the entries record the fingerprints above. The transaction’s call data holds, in order:

The law’s digests

Both laws are frozen, and their digests are written in the law texts. Unpack the source and compute them yourself; the results should match the table:

cd zikaron-0.1.4/base/zikaron-conformance ./criterion-digest.sh ./criterion-digest-kit.sh
zikaron/1 · §12.50xbecfb6f0d0f8b71c314f1b2efef414abfb6df74b711ca8f81efdef685d0132fc
zikaron.kit/1 · §13.50x3f8368ebc8b5b7c97e4b5c4240f57f6fc06421b4effbd5a7446d128434a20535

Each script reads a few Python source files and computes one digest; change any byte of them and the digest changes. See The law and the conformance suite.

The registry contract

The registry contract does one thing: it receives a fingerprint and emits an event. The app comes with four deployments, of which Ethereum mainnet, Arbitrum One and OP Mainnet are the same build at the same address. Read the code on chain and compute its keccak256, and the result should equal the code hash below:

cast keccak $(cast code <contract address> --rpc-url <node>)
Code hash0xfa97a1d9b22fab2b52f4e27c9a965b32734c40001b565ab365d05c887118f57d
Ethereum mainnet0x36Ea8A857a5FE813429d4D9947000C644A88809A

OP Mainnet0x36Ea8A857a5FE813429d4D9947000C644A88809A

How to recompute the hash from source is under The registry contract and anchoring.
