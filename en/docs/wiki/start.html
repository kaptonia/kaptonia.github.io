Getting started

Install

Download the package for your system from the download page; the steps for each system are there too.

  • Mac: before the first launch, in Terminal, remove the quarantine flag the download carries; the download page has the command to copy.
  • Windows: on first launch Windows says “Windows protected your PC”; click “More info”, then “Run anyway”. On Windows 11 with Smart App Control on, turn it off first as the download page shows.
  • Linux: install the .deb, or make the AppImage executable and run it.

When you upgrade from an earlier version, bring your ledger across first as Upgrading from an earlier version below describes.

Using it through an AI Agent

An AI Agent with a cloud computer can install ZIKARON and get it ready to work by itself, and you use it simply by talking with the agent. Hand it this text:

ZIKARON quick start (for an AI agent) 1. Fetch and install: download the latest package from the Releases of https://github.com/kaptonia/zikaron, check it against SHA256SUMS.txt, then install. On Linux: sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -o Dpkg::Options::=--force-confold ./zikaron-desk_*_amd64.deb 2. Read: README.md (networks and contract addresses) and CLI-SCHEMA.md (how to use each command). Once installed, run zikaron contract and go by the subcommands, flags and exit codes it lists. 3. Get to work: - If the user already runs ZIKARON Desk on their own computer, prefer --home or "With a credential", so the private key stays on the user's computer. - Otherwise: generate a key with zikaron keygen, save it in a file with mode 600 and keep it out of sight; ask the user whether they want a copy of the key file to keep; if so, hand it over as a file, never pasted into the chat, and remind them to store it offline; then create a ledger with zikaron init; ask the user to send a little ETH to the address for gas. 4. Every day: record with history --file → put on chain with anchor → check with scan, then audit; to share, export a record kit with kit-export, which the other side checks with kit-verify. Gather several records and put them on chain together, paying gas for one transaction. 5. Upgrading: check Releases regularly. For a new version, first read the release notes and the upgrading part of CHANGELOG, check the package against SHA256SUMS.txt, then install it over the old one as in step 1. Command-line ledger folders keep working across versions. If the release notes call for a migration by hand, tell the user first and go ahead once they agree. After upgrading, run zikaron contract to see whether any command changed. At every upgrade, remind the user to download a ledger backup (pack the ledger folder into one file and hand it over), and agree with them on regular backups from then on. 6. When the user wants the safer desktop app, walk them through it step by step: - Open the download page https://kaptonia.github.io/en/use.html, download for the user's system, check the SHA-256, then install. On a Mac, the quarantine mark comes off before the first launch; the download page has the command to copy. - First launch: set a passcode and write the recovery words on paper, kept somewhere offline. The recovery words stay with the user alone; ask them to keep the words to themselves. - Bring the ledger into the desktop, one of two ways: · Hand the private key to the user, who imports it with "Import key" in the desktop app and takes the ledger in with "Adopt existing ledger folder". After adoption, the desktop writes the original folder's ledger. · Write the ledger into a handoff file with hand-over and give it to the user, who takes it on the desktop side with take-over; from then on the ledger is written by turns in the two places. - Then ask the user to turn on "Through the desktop app" or "With a credential" in Settings › Command line; switch to --home or the credential, and delete the private key file in the cloud afterwards. 7. Rules: the private key and the recovery words stay out of chats and logs; one place writes a ledger at a time, and to move the writing use hand-over / take-over.

The details of each way are in Command line and AI Agents and remote operation.

Upgrading from an earlier version

This version reads the encrypted form it writes itself and starts from an empty machine folder; the key store, identities, settings and data an earlier version left stay where they are. Bring a Recorder’s ledger across in five steps:

  1. In 0.1.2, open Settings › Local data, press “Export ledger mirror”, save it to a folder outside the machine folder, then quit.
  2. Move the earlier machine folder aside together with its pointer file. On a Mac and on Linux the pointer file is .zikaron-desk in your home folder and the machine folder is .zikaron-desk.d by default; on Windows both are in %LOCALAPPDATA%\ZIKARON\.
  3. Open the new version, set a passcode, and at “Create an identity” press “Import an existing key” and import with the same recovery words.
  4. At “Create the ledger”, click “Adopt existing ledger folder”, choose the mirror’s ZIKARON-backup/<address>/author folder and press “Adopt in place”. Every entry is checked again and the ledger is checked against the records on chain; that completes the step.
  5. Run a ledger check on the Ledger page and see it read “OK”.

Other identities go the same way: import each with “Import key” from the identity chip, then take its mirror with “Adopt existing ledger folder” under “Advanced options” in Settings › Local data. Add received grants again in “My grants”, and set the network and other settings again. After upgrading, keep opening the data with the new version: earlier versions cannot read the files it writes.

First launch

A wizard opens, with six steps down the left:

  1. Set a passcode. 8 letters or digits, asked for each time the app opens.
  2. Create an identity. The app generates 12 recovery words; write them on paper, then fill three of them back in when asked. You can also import a key you already have, or restore from a whole-machine backup.
  3. Network. Choose “Ethereum mainnet”; the app comes with public nodes. To try it free first, choose “Custom”, then in Settings › Network press “Edit nodes”, pick “Sepolia testnet” under “Preset”, and press “Save nodes” and “Save chain settings”.
  4. Create the ledger. Write a line of description (or leave it empty) and press “Create the ledger”. Free. With a ledger already at hand (a ledger folder, or a mirror “Export ledger mirror” wrote), click “Adopt existing ledger folder” beside it, choose it under “Ledger folder” and press “Adopt in place”.
  5. Add gas. Send a little ETH to the address on the page, or scan the payment QR code with your wallet (it names the chosen network), and press “I have sent it”. You can choose “Later”.
  6. Whole-machine backup. Export a password-protected backup file. You can do it later; the sooner the better.

“中文” | “English” at the bottom left switches the language from the first step. “Back” returns to the previous page; on the page that checks the recovery words it returns to the same twelve words. Once the passcode and the identity are set, “Exit setup” (or Esc) is at the bottom left.

Keep the recovery words on paper, somewhere only you can reach. They bring back your keys; ledgers and settings come back from a whole-machine backup.

Your first record

Choose “Recorder” at the top of the sidebar.

  1. Record. Drop a file onto Home, fill in “Record name”, press “Add to ledger”, then press it again on the confirmation card.
  2. Put it on chain. Click the “Pending” card on Home, then press “Confirm and send” on the “Put on chain” card that opens. A few minutes later the state turns “Confirmed”.
  3. Grant. Open “Grant” and press “New grant”: fill in the other side’s address, choose this record, drop in a terms file, add it to the ledger and put it on chain the same way. See Grants.

Keep the original files safe: to prove something later, you show the very file the record was made from.

Receiving a grant

  1. Switch to “User” at the top of the sidebar.
  2. Paste the grant code you received into the “Verify a grant” card on Home and press “Start check”.
  3. Open “My grants”, press “Add grant”, paste the grant code or drop in the grant file, and press “Verify and add” to keep it. When it is about to expire or gets revoked, the Alerts page tells you.
