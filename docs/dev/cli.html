开发者指南 · Zikaron

命令行

zikaron 提供与窗口相同的账本操作，一个动作一个子命令。它面向脚本：输出是单个 JSON 值，结论体现在退出码里。完整的输出形状、退出码、拒绝原因与参数，见源码里的 CLI-SCHEMA.md；zikaron contract 也把这份契约由代码里的同一张表输出成一个值。

在哪里

用 dmg 安装的
/Applications/ZIKARON.app/Contents/MacOS/zikaron。在应用「设置 › 本机数据」打开「启用命令行」，它在 /usr/local/bin/zikaron 放一个链接，需要时 macOS 弹出管理员口令框；这个开关要在拖进「应用程序」之后的应用里打开。
用 pkg 安装的
/usr/local/bin/zikaron，装完即可用；「启用命令行」显示「被其他安装占用」，保持原样即可。
用 deb 安装的
/usr/bin/zikaron；「启用命令行」显示「已由安装包提供」。用 AppImage 时，要用命令行请装 .deb，开关显示「此安装方式不支持」。
Windows
解压出的文件夹里的 zikaron.exe，在终端里运行，双击它只会一闪而过。「启用命令行」把这个文件夹写进本用户的 Path，之后新开的终端才认得 zikaron。
从源码构建的
target/release/zikaron；「启用命令行」在 macOS 上链到 /usr/local/bin，在 Linux 上链到 ~/.local/bin，这个文件夹要在 PATH 里。

三条约定

标准输出是单个规范 JSON 值
每次调用输出一个值，以值的最后一个字符结束。字节格式依法 §3.4：紧凑书写，成员按字节序排列。
误用时标准输出为空
参数有误、路径读取失败时，退出码为 2，标准输出零字节，标准错误的第一行写作 <原因> <对象>。对象只用命令行自己的名字：参数表里的旗写作 --名字，其余的值与路径只写它在参数里排第几、有多长，如 E_UNREADABLE #3 (15 bytes)，所以私钥、带访问密钥的节点地址都留在你自己手里，终端与日志里只有位置和长度。第二行是给人看的说明，按系统语言（LC_ALL、LC_MESSAGES、LANG、LANGUAGE 中第一个设了的）是中文时用中文，否则用英文，不属约定。调用方凭标准输出是否为空，即可分清答案与误用。
状态词原样传出
GREEN、PARTIAL、FAIL、COMPLETE、GAPS 等由核写出，命令行原样传出。

写条目被法拒收时（E_ENTRY，其 token 为 E_BODY_FIELD，退出码 1），标准错误另有一行人话，点名是哪一项、由哪个参数给，例如 statement_md: 缺或不成形,由 --statement 给；这一行同样随系统语言，属于给人看的说明，标准输出与退出码与它无关。

写文件只有一种方式：--out 先在旁边写完整个临时文件、落盘，再改名到位；同名文件已经存在时，这次写入作罢，原文件一个字节都保持原样。

退出码

码含义示例
0已答，答案肯定GREEN、COMPLETE
1已答，答案否定条目被拒，写入会把账本写断（E_WOULD_BREAK），节点以关乎这一笔的理由拒绝估 gas 或估数超过 200,000（E_GAS_REFUSED），交易入块而执行失败（E_TX_STATUS），先前发出的那一笔已作废（E_TX_VOID），授权文件拆不开（E_GRANT_FILE），记录包不成立（E_KIT），经桌面的 attest（E_ON_DESKTOP），桌面拒绝这一动作（E_DESKTOP_REFUSED，网络方面的除外），或结论为 FAIL、BROKEN_CHAIN、NO_LABEL
2误用参数有误、路径读取失败、--key 与 --key-file 同给、密钥文件他人可读、--form registry 缺 --registry、给 --home 的动词或旗不收它；标准输出为空
3已答，介于两者之间PARTIAL、GAPS、UNAVAILABLE；经桌面的 anchor 只入了队（E_QUEUED）
4答案缺席节点失联、多个节点读数相左、扫描被拒、取不到随机数、节点出于自身缘由拒绝估 gas（E_UNREACHABLE）、桌面没有答（E_DESKTOP）、桌面因网络拒绝（E_DESKTOP_REFUSED）

3 与 4 各占一个码，是这张表的分量所在。把「尚未上链」并入 0，买方会把尚待锚定的授权当作放行；并入 1，一次「暂不可知」会被读成「伪造」。把「节点不通」并入 1，一次网络故障会被读成「这条链是假的」。扫描失败是答案缺席，调用方应重试或换节点。

二十二个子命令

子命令作用
keygen生成一把密钥，输出地址与私钥
init ✦在空账本上写创建账本条目
history ✦追加一条存证（--file 按应用的约定记一份文件）
grant ✦签一份授权并写入账本
revoke ✦签一份撤销并写入账本（裁决文件摘要可选）
adopt ✦写一条导入条目；连署只给了两半之一的即拒
attest ✦用外部密钥出一份连署
succeed ✦写一条换密钥或移交条目
annotate ✦写一条注记
retract ✦写一条删除条目（目标须是本账本里一条现存的存证）
anchor ✦把哈希锚定上链：调用登记合约，或自转账裸锚；发前先估 gas，重跑先问
scan按链设置扫描锚（--endpoint 收 http 与 https）
audit用扫描结果加账本做审计，输出报告与结论（--ledger 收账本目录、账本镜像或记录包；--out 另存这一趟的审计输入）
check-grant六项核验一份授权（--grant 收授权条目文件或 .zkgrant 授权文件）
chain-check逐跳核验转授权链（--hop <授权文件>[=<审计输入文件>]，可重复）
depth一件记录的深度读数
fpm-sign签指纹清单
ack-sign签收执
badge编码或解码凭证（--encode 与 --decode 二选一）
kit-export ✦导出记录包，自验通过才写出
show显示一条条目的作者、ID、类型、上一条、序号与内容
contract输出命令行自己的契约：动词、各动词的参数（带 --home 时的另一张）、退出码与拒因

标 ✦ 的十一个收 --home，见下文经桌面。子命令之外的第一个词按误用处理，退出码为 2。

参数

五十六个参数一律是长参数，且每个都带一个值；每个子命令有自己的一张参数表，表外参数按误用处理。条目正文中法所要求的成员，在命令行上都可以省略；省略后由核依法拒收，命令行只检查它自己做事所必需的几项。这样判断规则只在核里存在一份。

--key-file
从文件读私钥，代替 --key，两者择一；文件须只本人可读。凡收 --key 的子命令都收它。
--proxy
anchor 与 scan 收：system（默认）、none，或 http://主机:端口、socks5://主机:端口。本机节点一律直连。system 在 macOS 与 Windows 上读系统设置，在 Linux 上读 https_proxy、http_proxy、all_proxy、no_proxy；应用里的代理设置只管应用自己。
--home
交给正在运行的桌面应用代做，见下文。

各子命令的参数表与环境变量（每一问的总期限 ZKA_TIMEOUT_SECS，默认 30 秒；应答上限 ZKA_MAX_ANSWER_BYTES，默认 64 MiB 等）都写在 CLI-SCHEMA.md 里。

示例

生成密钥、创建账本、存证一份文件、上链、审计：

zikaron keygen # {"address":"0x…","ok":true,"privkey":"0x…"} zikaron init --ledger ./ledger --key-file ./key.txt --statement "作品存证" zikaron history --ledger ./ledger --key-file ./key.txt --file 手稿.pdf # {"entryId":"0x…","ledger":"…","ok":true,"seq":1,"written":true} zikaron anchor --key-file ./key.txt --endpoint <链号>=<节点> \ --form registry --registry <合约地址> --hash <entryId> zikaron scan --endpoint <链号>=<节点一> --endpoint <链号>=<节点二> \ --basis basis.json > fragment.json zikaron audit --ledger ./ledger --fragment fragment.json echo $?

history --file 按应用记录文件的同一约定填：content 是这份文件字节的 SHA-256，mode 是 {"mark":"bytes-sha256/1","toolchain":<"bytes-sha256/1" 这串字的 SHA-256>}；同一份文件，命令行与应用记下的这两项逐字相同。也可以不用 --file，自己给 --content、--mark、--toolchain 三项，两种写法不能同给。

节点地址可以是 http:// 或 https://，大小写都认，IPv6 写成方括号形；https 用编进程序的根证书校验证书链与主机名，与应用同一个连法。每一问有一个 30 秒的总期限，一个地址解析出几个 IP 时逐个试，读类的问在连接中途断开时换新连接再问一次，交易只广播一次；地址里带的访问密钥在一切输出里都隐去。

anchor 恰好收一个 --endpoint：它读这个节点的基础费与最近 20 块的成交小费，按应用的同一条规则定费（取中位数大于零的块，块块为零时取零），再请节点按这一笔交易估一次 gas，所带额度是估数的 1.5 倍（向上取整），最多 200,000。节点以关乎这一笔的理由拒绝估（会回滚），或估数超过 200,000，即拒 E_GAS_REFUSED；节点出于自身缘由拒绝（限流、不支持这一问、要凭据、链不符等），或没答，报 E_UNREACHABLE；两种情形都在广播之前停下。发出之后，它按间隔一轮轮问收据，直到 --wait-secs 用完。

重跑先问。自持私钥运行的 anchor 把它为同一次锚定（同一条链、同一把钥、同一个去处、同一段数据）签过的每一笔交易的 nonce 与哈希，在广播之前记进机器目录的 cli-sent/，只记这两项。同一条命令再跑时，先按哈希问节点：已入块即照答；还在节点池里就接着等收据；都不在而 nonce 没被用掉，按同一个 nonce 重签再发，至多一笔能入块；nonce 已被别的交易用掉即答 E_TX_VOID 并停下，再跑一次即重新发起。所以成功之后把同一条命令再跑一遍，答的是先前那一笔，一次锚定只付一次费。

scan 的每一问都带上扫描范围里的发送者，只取这些地址的日志；节点拒答时原样再问，连拒三次才把范围拆小。basis.json 写明扫描范围：哪些链、哪些登记合约、哪些发送地址、起止区块，格式见法 §9.4。命令行不记已核对的事实，每次扫描都问遍每一条日志。

写之前先审

每个写条目的子命令（含 init 与 retract）都过同一道门：条目签好之后，核把「这个账本加上这一条」离线审一遍，会新添一条法 §8.3 的链上发现（换钥之后旧钥再写、跳号、同一位置写第二条、接错上一条）即拒 E_WOULD_BREAK，names 写明是哪几种，一个字节也不写。手给 --seq、--prev 也一样过这一道。账本有两个根而没给 --root 时，写入一律拒 E_TIP_FORKED。

经桌面

给 --home <桌面的数据目录> 时，标 ✦ 的十一个子命令交给正在运行、已解锁、并以写者打开这个数据目录的 ZIKARON Desk 去做：条目以桌面的身份写进桌面的账本，窗口里随即可见；私钥与口令都留在桌面里，写入全由桌面完成。

  • 桌面开着这个数据目录时，为它开一条本机通道：macOS 与 Linux 上是机器目录里一个只本人可读写的套接字文件，Windows 上是只本用户够得着的命名管道。连上之后两端各问系统对方以谁的身份运行，不是同一用户即拒。锁定、关掉或换掉数据目录、退出应用，通道随即关闭。
  • 参数照常先判误用；带 --home 时各子命令另有一张参数表，账本、密钥与序号由桌面自己定（如 history 收 --file 与 --note，anchor 只收 --home），表外的参数算误用。请求按到达的次序逐个做，在桌面里走与点按同一条动作路径。
  • anchor 照桌面「设置 › 网络」的「命令行上链」：「自动发送」照队列页的「全部上链」发出；「仅加入队列」只入队，答 E_QUEUED（退出码 3）。
  • attest 一律答 E_ON_DESKTOP：连署要口令，口令只在桌面上输。kit-export 收 --entry、--note、--out，附件与证明包在桌面上选。
  • 桌面锁着、没开这个数据目录或已退出时答 E_DESKTOP（退出码 4）；桌面拒绝这一动作时答 E_DESKTOP_REFUSED，token 是桌面自己的代码。

带 --home 的命令行按桌面同一个规则找机器目录。各子命令带 --home 时收哪些参数，见 CLI-SCHEMA.md 第 11 节。

时间由调用方注入

期限与时段只按链上时间和 --now 注入的时刻判断；省略 --now 即只用链上时间。时刻都由调用方给出，所以同一输入始终得到同一结论。

读应用自己的账本

ZIKARON Desk 数据目录里的账本是加密的（文件以 zikaron-local/2 开头，早先版本写的以 zikaron-local/1 开头），口令只在应用里，命令行读到时按误用拒绝，退出码为 2：

E_UNREADABLE #3 (40 bytes) 已锁定:这是 ZIKARON Desk 封存的本机数据,命令行不读

要往应用自己的账本里写，用 --home 交给桌面代做。要交给命令行读，先在应用里导出「账本镜像」或「记录包」：audit（以及经它的 check-grant、chain-check、depth）和 show --entry 的 --ledger 可以直接指向镜像文件夹（含 mirror.json 的那一层）或记录包文件夹；记录包先按记录包的法核一遍，不成立即拒 E_KIT。写条目的子命令与 init 在命令行一侧只收账本目录：要在命令行一侧接着写，把镜像 entries/ 里的文件复制到一个空文件夹，并在文件名后加 .entry。
