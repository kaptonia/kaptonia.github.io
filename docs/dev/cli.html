开发者指南 · Zikaron

命令行

zikaron 提供与窗口相同的账本操作，一个动作一个子命令。它面向脚本：输出是单个 JSON 值，结论体现在退出码里。完整的输出形状、退出码、拒绝原因与参数，见源码里的 CLI-SCHEMA.md。

在哪里

用 dmg 安装的
/Applications/ZIKARON.app/Contents/MacOS/zikaron
用 pkg 安装的
/usr/local/bin/zikaron
用 deb 安装的
/usr/bin/zikaron；AppImage 里也带着命令行，但不能直接调用
Windows
解压出的文件夹里的 zikaron.exe，要从任意位置调用，自己把这个文件夹加进 PATH
从源码构建的
target/release/zikaron

三条约定

标准输出是单个规范 JSON 值
每次调用输出一个值，以值的最后一个字符结束。字节格式依法 §3.4：紧凑书写，成员按字节序排列。
误用时标准输出为空
参数有误、路径读取失败时，退出码为 2，标准输出零字节，标准错误的第一行写作 <原因> <对象>，如 E_UNREADABLE /nowhere/at/all，对象只写出错的那一个参数、值或路径；第二行是给人看的说明，不属约定。调用方凭标准输出是否为空，即可分清答案与误用。
状态词原样传出
GREEN、PARTIAL、FAIL、COMPLETE、GAPS 等由核写出，命令行原样传出。

写条目被法拒收时（E_ENTRY，其 token 为 E_BODY_FIELD，退出码 1），标准错误另有一行人话，点名是哪一项、由哪个参数给，例如 mode: 缺或不成形,由 --mark 与 --toolchain(或 --file) 给；这一行同样不属约定，有没有它，标准输出与退出码都一样。

写文件只有一种方式：--out 先在旁边写完整个临时文件、落盘，再改名到位；同名文件已经存在时，这次写入作罢，原文件一个字节都保持原样。

退出码

码含义示例
0已答，答案肯定GREEN、COMPLETE
1已答，答案否定条目被拒，写入会把账本写断（E_WOULD_BREAK），节点答这笔交易会失败或估数超过 200,000（E_GAS_REFUSED），授权文件拆不开（E_GRANT_FILE），记录包不成立（E_KIT），或结论为 FAIL、BROKEN_CHAIN、NO_LABEL
2误用参数有误、路径读取失败，标准输出为空
3已答，介于两者之间PARTIAL、GAPS、UNAVAILABLE
4答案缺席节点失联、多个节点读数相左、扫描被拒、取不到随机数

3 与 4 各占一个码，是这张表的分量所在。把「尚未上链」并入 0，买方会把尚待锚定的授权当作放行；并入 1，一次「暂不可知」会被读成「伪造」。把「节点不通」并入 1，一次网络故障会被读成「这条链是假的」。扫描失败是答案缺席，调用方应重试或换节点。

二十一个子命令

子命令作用
keygen生成一把密钥，输出地址与私钥
init在空账本上写创建账本条目
history追加一条存证（--file 按应用的约定记一份文件）
grant签一份授权并写入账本
revoke签一份撤销并写入账本（裁决文件摘要可选）
adopt写一条导入条目
attest用外部密钥出一份连署
succeed写一条换密钥或移交条目
annotate写一条注记
retract写一条删除条目（目标须是本账本里一条现存的存证）
anchor把哈希锚定上链：调用登记合约，或自转账裸锚；发前先估 gas
scan按链设置扫描锚（--endpoint 收 http 与 https）
audit用扫描结果加账本做审计，输出报告与结论（--ledger 收账本目录、账本镜像或记录包；--out 另存这一趟的审计输入）
check-grant六项核验一份授权（--grant 收授权条目文件或 .zkgrant 授权文件）
chain-check逐跳核验转授权链（--hop <授权文件>[=<审计输入文件>]，可重复）
depth一件记录的深度读数
fpm-sign签指纹清单
ack-sign签收执
badge编码或解码凭证（--encode 与 --decode 二选一）
kit-export导出记录包，自验通过才写出
show显示一条条目的作者、ID、类型、上一条、序号与内容

子命令之外的第一个词按误用处理，退出码为 2。

参数

五十三个参数一律是长参数，且每个都带一个值；每个子命令有自己的一张参数表，表外参数按误用处理。条目正文中法所要求的成员，在命令行上都可以省略；省略后由核依法拒收，命令行只检查它自己做事所必需的几项。这样判断规则只在核里存在一份。各子命令的参数表与环境变量（读链超时 ZKA_TIMEOUT_SECS，默认 30 秒；应答上限 ZKA_MAX_ANSWER_BYTES，默认 64 MiB 等）都写在 CLI-SCHEMA.md 里。

示例

生成密钥、创建账本、存证一份文件、上链、审计：

zikaron keygen # {"address":"0x…","ok":true,"privkey":"0x…"} zikaron init --ledger ./ledger --key <私钥> --statement "作品存证" zikaron history --ledger ./ledger --key <私钥> --file 手稿.pdf # {"entryId":"0x…","ledger":"…","ok":true,"seq":1,"written":true} zikaron anchor --key <私钥> --endpoint <链号>=<节点> \ --form registry --registry <合约地址> --hash <entryId> zikaron scan --endpoint <链号>=<节点一> --endpoint <链号>=<节点二> \ --basis basis.json > fragment.json zikaron audit --ledger ./ledger --fragment fragment.json echo $?

history --file 按应用记录文件的同一约定填：content 是这份文件字节的 SHA-256，mode 是 {"mark":"bytes-sha256/1","toolchain":<"bytes-sha256/1" 这串字的 SHA-256>}；同一份文件，命令行与应用记下的这两项逐字相同。也可以不用 --file，自己给 --content、--mark、--toolchain 三项，两种写法不能同给。

节点地址可以是 http:// 或 https://，大小写都认；https 用编进程序的根证书校验证书链与主机名，与应用同一个连法。anchor 恰好收一个 --endpoint：它读这个节点的基础费与最近 20 块的成交小费，按应用的同一条规则定费，再请节点按这一笔交易估一次 gas，所带额度是估数的 1.5 倍（向上取整），最多 200,000；节点答这笔会失败、或估数超过 200,000 时拒发 E_GAS_REFUSED，节点没答时报 E_UNREACHABLE，两种情形都一笔也不发。发出之后，它按间隔一轮轮问收据，直到 --wait-secs 用完。

scan 的每一问都带上扫描范围里的发送者，只取这些地址的日志；节点拒答时原样再问，连拒三次才把范围拆小。basis.json 写明扫描范围：哪些链、哪个登记合约、哪些发送地址、起止区块，格式见法 §9.4。命令行不记已核对的事实，每次扫描都问遍每一条日志。

写之前先审

每个写条目的子命令（含 init 与 retract）都过同一道门：条目签好之后，核把「这个账本加上这一条」离线审一遍，会新添一条法 §8.3 的链上发现（换钥之后旧钥再写、跳号、同一位置写第二条、接错上一条）即拒 E_WOULD_BREAK，names 写明是哪几种，一个字节也不写。手给 --seq、--prev 也一样过这一道。账本有两个根而没给 --root 时，写入一律拒 E_TIP_FORKED。

时间由调用方注入

期限与时段只按链上时间和 --now 注入的时刻判断；省略 --now 即只用链上时间。时刻都由调用方给出，所以同一输入始终得到同一结论。

读应用自己的账本

ZIKARON Desk 数据目录里的账本是加密的，口令只在应用里，命令行读到时按误用拒绝，退出码为 2：

E_UNREADABLE <账本路径> 已锁定:这是 ZIKARON Desk 封存的本机数据,命令行不读

要交给命令行处理，先在应用里导出「账本镜像」或「记录包」。audit（以及经它的 check-grant、chain-check、depth）和 show --entry 的 --ledger 可以直接指向镜像文件夹（含 mirror.json 的那一层）或记录包文件夹；记录包先按记录包的法核一遍，不成立即拒 E_KIT。写条目的子命令与 init 只收账本目录：要接着写，把镜像 entries/ 里的文件复制到一个空文件夹，并在文件名后加 .entry。
