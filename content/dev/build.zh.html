一个 Rust 工作区：一条命令构建，一条命令测试，各平台用各自的脚本或命令打包。

环境要求

Rust
stable 版，2021 edition，用 rustup 安装。
C 工具链
TLS 用到的加密库 ring 要为本机编译一段 C 代码。在 macOS 上装 Xcode 的命令行工具；在 Windows 上用 MSVC 工具链（目标 x86_64-pc-windows-msvc）。
Linux 的系统库
窗口、键盘与文件对话框所需的开发包，见下文。
Python 3
运行法的冻结核与一致性比对，只用标准库。
Foundry
测试登记合约、重算代码哈希时使用。

在 Debian 或 Ubuntu 上，先装构建依赖：

{{code: sudo apt install build-essential pkg-config libxkbcommon-dev libxkbcommon-x11-0 \ libwayland-dev libx11-dev libxcursor-dev libxrandr-dev libxi-dev libgl1-mesa-dev \ xdg-desktop-portal xdg-desktop-portal-gtk }}

Linux 上的系统文件对话框走桌面门户，所以运行时要有 xdg-desktop-portal 和一个后端；缺少门户时，把文件直接拖进窗口即可。

构建时，crates/app/build.rs 用 cargo metadata --locked --offline 按目标平台从 Cargo.lock 现生成第三方许可清单，随应用一起带着；清单生成不了，构建即失败。依赖增删之后，清单自动跟着变。

构建与测试

{{code: tar -xzf zikaron-{{VER}}-src.tar.gz cd zikaron-{{VER}} cargo build --release --locked cargo test --workspace }}

--locked 让构建严格使用 Cargo.lock 锁定的依赖版本，发布包也这样构建。产物：

程序是什么
target/release/app桌面窗口，在 macOS 上打包为 ZIKARON.app，在 Linux 上为 zikaron-desk，在 Windows 上为 zikaron-desk.exe
target/release/zikaron命令行，见命令行
zk1、zkk、zks、zka、zkg供测试与一致性比对用的辅助程序
zikaron-pack打包工具：生成第三方许可清单，去掉包里的构建机信息，排出 Windows 包

每次推到 main 和每个合并请求，仓库的 .github/workflows/test.yml 都在 macOS、Linux 与 Windows 上跑 cargo build --workspace --locked 和 cargo test --workspace --locked；macOS 与 Linux 两格必须通过，Windows 一格在 Windows 实机上走通之后才列为必过。

打包

脚本或命令产出
packaging/macos/build.sh [--identity NAME]ZIKARON.app，装在 .dmg 和 .pkg 里(macOS)
packaging/linux/build.sh.deb 与 AppImage，在 x86_64 或 aarch64 的 Linux 上本机构建；需要 dpkg-deb，以及 appimagetool（或能联网去取）
packaging/linux/cross-build.sh在别的主机上用 zig 与 cargo-zigbuild 打出同样的 Linux x86_64 包，目标 glibc 2.31；另需 mksquashfs、python3、curl
cargo run --release --locked -p zikaron-pack -- windows --out distWindows x86_64 包的文件夹 dist/ZIKARON-<版本>-windows-x86_64/：zikaron-desk.exe、zikaron.exe、LICENSE.txt、THIRD-PARTY-LICENSES.txt。在 Windows 上用 MSVC 构建，C 运行库静态链接，用户那边无需另装运行库；.github/workflows/package-windows.yml 手动触发时调的就是这一条。直接 cargo build 出的 Windows 程序动态链接 C 运行库，要另装 VC++ 运行库

macOS 与 Linux 的包落在 dist/，各附一份 SHA256SUMS-<系统>-<架构>.txt；Windows 那一条只排出文件夹，发布页上的 zip 由这个文件夹压成。每个包都带按目标平台现生成的 THIRD-PARTY-LICENSES.txt，包里不带构建机的用户名、属主、主机或系统版本。macOS 脚本省略 --identity 时做临时签名(-)；发布包用 Kaptonia 的证书签名，见发布。

deb 声明的运行依赖：libc6、libdbus-1-3、libgcc-s1、libxkbcommon0、libxkbcommon-x11-0、libwayland-client0、libx11-6、libxcursor1、libxrandr2、libxi6、libgl1；推荐 xdg-desktop-portal 与 xdg-desktop-portal-gtk。

用独立数据试用

在 macOS 与 Linux 上，应用从 HOME 找机器目录，密钥库也只住在那里。把 HOME 指向一个空目录后启动，机器目录、密钥库与账本都落在其中，与日常数据隔离：

{{code: T=$(mktemp -d) HOME=$T ./target/release/app }}

Windows 上的主目录取自系统的用户配置文件，机器数据在 %LOCALAPPDATA%\ZIKARON\；要隔离，换一个 Windows 用户试用。

试用时，在向导里选「自定义」，再到「设置 › 网络 › 编辑节点…」的「预设」里选 Sepolia 测试网；或用「新建身份…」，在「网络」里选「Sepolia 测试网」，见 Wiki 的网络。测试用的密钥用 zikaron keygen 现场生成，用后即弃。

内嵌字体

界面的西文字体 Inter 与等宽字体 JetBrains Mono 内嵌于应用。中文在 macOS 上取自系统的苹方，在 Windows 上取自系统的微软雅黑（Microsoft YaHei UI，加粗用它的粗体），找不到时用内嵌的 Noto Sans SC，在 Linux 上用内嵌的 Noto Sans SC；所以 Noto Sans SC 只随 Windows 与 Linux 的构建内嵌。内嵌字体都以 SIL OFL 1.1 发布，许可文本在 crates/zikaron-ui/fonts/。
